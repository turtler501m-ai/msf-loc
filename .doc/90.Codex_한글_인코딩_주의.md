# Codex 한글 인코딩 주의

작성일: 2026-05-07

## 확인한 내용

참고 문서:
https://www.uniflow.kr/codex%EC%97%90%EC%84%9C-%ED%95%9C%EA%B8%80-%EB%AC%B8%EC%9E%90%EC%97%B4%EC%9D%B4-%EA%B9%A8%EC%A7%80%EB%8A%94-%EB%AC%B8%EC%A0%9C%EC%9D%98-%EC%9B%90%EC%9D%B8%EA%B3%BC-%EC%98%81%ED%96%A5/

요지는 Codex가 한국어를 처리하지 못해서 깨지는 문제가 아니라, Windows와 PowerShell 실행 경로에서 파일을 읽고 쓰는 인코딩이 UTF-8이 아닌 시스템 코드페이지로 되돌아가면서 한글 문자열이 손상될 수 있다는 것이다. 특히 한글 UI 문구, JSON, Markdown, Java 메시지처럼 한글 문자열이 많은 파일은 전체 파일 재작성이나 자동 포맷팅을 하면 피해 범위가 커진다.

이 작업공간에서도 `ManageDevPage.vue`를 PowerShell `Set-Content`로 다시 저장하는 과정에서 한글 UI 문구가 깨진 사례가 있었다. 해당 변경은 즉시 되돌리고 `apply_patch` 방식으로 필요한 부분만 다시 수정했다.

## 작업 규칙

1. 한글이 포함된 파일은 UTF-8로 취급한다.
2. 한글 포함 파일은 PowerShell `Set-Content`, `Out-File`, `>`/`>>` 리다이렉션, 전체 파일 read/write 스크립트로 저장하지 않는다.
3. 수동 수정은 `apply_patch`를 우선 사용한다.
4. 한글 UI 문구, 메시지, 주석, Markdown은 필요한 줄만 좁게 수정한다.
5. 전체 파일 포맷팅, 대량 치환, 생성 스크립트 재작성은 사용자가 명시적으로 요청하지 않는 한 피한다.
6. 부득이하게 기계적 변환이 필요하면 UTF-8 보존을 명시하고, 변환 직후 diff를 확인한다.
7. 수정 후 `git diff --check`를 실행하고, diff에서 `�`, `?좎`, `媛`, `怨` 같은 깨진 문자열이나 깨진 따옴표/태그가 생겼는지 확인한다.

## 권장 편집 방식

안전한 방식:

```text
apply_patch로 필요한 블록만 수정
git diff --check
git diff로 한글 문자열 손상 여부 확인
필요한 백엔드/프론트 검증만 실행
```

피해야 할 방식:

```powershell
Get-Content -Raw file | ... | Set-Content file
Out-File file
echo ... > file
스크립트로 Vue/Java/Markdown 파일 전체 재저장
```

## 이번 작업에서 적용한 조치

- `.AGENTS.md`에 Codex 작업자가 먼저 읽을 수 있는 인코딩 안전 규칙을 추가했다.

- 앞으로 한글 포함 파일은 patch-only 방식으로 수정하고, PowerShell 전체 저장은 사용하지 않는다.
